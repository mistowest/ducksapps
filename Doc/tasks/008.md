## Objetivo
Implementar sequências de chamadas que formam ações úteis (comportamentos de bot) baseado na análise do app, com pré-condições e efeitos colaterais claros, conforme definido na Fase 7 da metodologia.

## Contexto (leitura obrigatória)
- Todas as análises anteriores (00-overview.md através de 07-erros-rate-limit-paginacao-tempo-real.md)
- Todos os serviços implementados (auth_service.dart, user_service.dart, etc.)
- Doc/templates/endpoint-template.md (para entender padrões de endpoints)
- CLAUDE.md - seção Fase 7: Comportamentos de bot

## Especificação
Com base na análise completa do app, implementar classes que encapsulem sequências de chamadas de API que formam ações de negócio completas, com tratamento adequado de pré-condições, efeitos colaterais e estados intermediários.

### Assinaturas das funções/classes a criar
- `class BotBehaviors` - Classe principal contendo comportamentos de bot como métodos estáticos ou instância
- Ou comportamentos separados por domínio: `class AuthBehaviors`, `class FeedBehaviors`, etc.
- Cada comportamento deve ser um método que retorna `Future<void>` ou `Future<T>` com resultado significativo
- Exemplos de comportamentos baseado em apps sociais comuns:
  - `Future<void> signupAndOnboard(String email, String password, String username)`
  - `Future<Post> createPostWithImage(String caption, File image)`
  - `Future<void> followUser(String userId)`
  - `Future<List<Post>> getFeedSince(DateTime since)`
  - `Future<void> likePost(String postId)`
  - `Future<void> commentOnPost(String postId, String comment)`
  - `Future<void> refreshAuthIfNeeded()` - comportamento de manutenção

### Valores exatos (baseados em análise de endpoints descobertos)
Deve-se basear nos endpoints descobertos nas análises anteriores:
- Endpoints de auth: /token, /me, /logout, /refresh
- Endpoints de usuários: conforme descobertas em 04-usuarios.md
- Outros endpoints conforme descobertas em análises de feed, comunidades, etc. (se houver)

### Algoritmos em pseudocódigo
```
// Comportamento: Fazer login e garantir que o perfil esteja completo
Future<User> loginAndEnsureProfile(String email, String password) async {
  // Pré-condição: não autenticado
  final user = await authService.login(email, password);
  
  // Efeito colateral: token salvo, usuário autenticado
  
  // Verificar se perfil precisa ser completado
  final profile = await userService.getMe();
  if (profile.needsSetup()) {
    // Executar etapas de onboarding
    await _completeOnboarding(profile);
  }
  
  return user;
}

// Comportamento: Publicar conteúdo com tratamento de erro e retry
Future<Post> createContent(String content, {List<Media>? media}) async {
  // Pré-condição: autenticado
  if (!await authService.isAuthenticated()) {
    throw NotAuthenticatedException('Must be authenticated to create content');
  }
  
  try {
    final post = await apiService.createPost(content, media: media);
    // Efeito colateral: novo post criado, feed atualizado
    return post;
  } on RateLimitException catch (e) {
    // Tratar rate limit com espera exponencial
    await _handleRateLimit(e);
    return await apiService.createPost(content, media: media); // retry
  }
}

// Comportamento de manutenção: manter sessão viva
Future<void> maintainSession() async {
  if (await authService.isAuthenticated()) {
    final needsRefresh = await authService.tokenNeedsRefreshSoon();
    if (needsRefresh) {
      await authService.refreshToken();
    }
  }
}
```

### Regras de erro
- Cada comportamento deve validar suas pré-condições claramente
- Tratar erros de transição de estado adequadamente (ex: token expirado durante operação)
- Implementar retry com backoff exponencial para erros transitórios
- Nunca deixar o app em estado inconsistente - usar transações ou rollback quando possível
- Propagar erros de negócio (como conteúdo inválido) enquanto trata erros técnicos internamente

## Fora de escopo
- Implementação de comportamentos para endpoints ainda não descobertos
- Otimização avançada de caching além do básico
- Implementação de fila de tarefas ou processamento assíncrono complexo
- Comportamentos que requerem acesso a recursos de dispositivo não analisados (câmera, GPS, etc.) sem evidências
